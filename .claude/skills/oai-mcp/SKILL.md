# OAI MCP server + OAuth

Full reference: `oai/docs/mcp.md`. This skill is the working map.

## Shape

- **Transport** `mcp/mod.rs`: stateless Streamable HTTP. One JSON body per request, no
  `Mcp-Session-Id`, `GET`/`DELETE` → 405, notifications → 202. Dual-era:
  `initialize` for 2024-11-05…2025-11-25; modern `2026-07-28` via `_meta` protocol
  version + `server/discover` (header/body mismatch → 400 `-32020`, bad version → 400
  `-32022`, unknown method → 404). Every result gets `resultType: "complete"`.
- **Auth** `mcp/auth.rs`: `Authorization: Bearer` only (never cookie / `?token=`). OAuth
  access token (sha256 lookup in `oauth_tokens`) or an OAI user JWT fallback. 401 carries
  `WWW-Authenticate: Bearer resource_metadata="{base}/.well-known/oauth-protected-resource/mcp"`.
  That header is what starts Claude's OAuth flow.
- **Tools** `mcp/tools/{images,prompts,placeholders}.rs`: each mirrors an `oai image …`
  CLI command and calls the **service layer directly** (`image_jobs`, `db::prompts`,
  `prompt_previews`, `db::prompt_placeholders`). Never call our own HTTP API.
  Registry/annotations in `tools/mod.rs`; `Id` accepts string or number IDs.
- **Results** `mcp/content.rs`: `ToolOutput` (text + inline JPEG + `structuredContent`).
  Errors become `isError: true`, not JSON-RPC errors. The inline image budget is
  `INLINE_IMAGE_BUDGET` (110k base64 chars), because Claude caps a tool result at ~150k
  chars.
- **Signed links** `mcp/files.rs`: `/mcp/files/{id}?u&exp&sig`, HMAC from
  `Auth::sign_link` (key derived from `JWT_SECRET`), TTL `MCP_FILE_LINK_TTL_HOURS`.
- **OAuth** `services/oauth.rs` (protocol) + `routes/oauth.rs` (HTTP + consent HTML) +
  `db/oauth.rs` (4 tables, migration `m20261009_000035`): DCR (public clients, https or
  loopback-http redirects), S256 PKCE, codes 5 min single-use, access 1 h, refresh 30 d
  rotating with reuse detection, RFC 7009 revoke, password change revokes all grants.
- **Expansion** `services/prompt_expansion.rs`: Rust port of
  `frontend/src/lib/promptPlaceholders.ts`. Dictionaries in
  `services/placeholder_dicts/*.txt`, regenerated by
  `oai/backend/scripts/gen-placeholder-dicts.mjs` from the frontend's
  `unique-names-generator`. Behaviour is pinned to the web UI by
  `matches_the_web_ui_expander_on_edge_cases`: to refresh the expected values when
  `promptPlaceholders.ts` changes, import that `.ts` file directly with Node 24 (type
  stripping; no build) and print `expandPromptPlaceholders(case, createPlaceholderUsage(),
  defs)`. The expander also records unknown `{tokens}` and depth-cap hits
  (`expansion_warnings` in `tools/placeholders.rs`), and jobs expose `prompt_template`.

## Rules

1. **Claude limits:** tool call 240 s → `MAX_WAIT_SECS` = 200; OAuth endpoints must answer
   in under 10 s; `/oauth/token` must accept form-urlencoded; error codes must follow RFC
   6749 (`invalid_grant` for a dead refresh token, 401 `invalid_client` for an unknown
   client, which triggers re-registration).
2. **No per-IP rate limit** on `/mcp`, `/oauth/token`, `/oauth/register`: all Claude
   traffic shares `160.79.104.0/21`. Only `POST /oauth/authorize` (bcrypt, user browser)
   is limited.
3. A still-running job is a normal result ("call get_image_job"), never an error.
4. New `oai image` CLI feature → add the tool here and a row in `docs/mcp.md`. Keep tool
   names snake_case, descriptions explicit about the CLI equivalent, annotations honest
   (`destructiveHint` on deletes).
5. `PUBLIC_BASE_URL` must equal the origin users type into Claude (Helm sets it from
   `ingress.host`). The `resource` in metadata must match `{base}/mcp` exactly.

## Verify

```bash
cd oai/backend && cargo test mcp:: && cargo test oauth && cargo test prompt_expansion
# against a throwaway backend (see memory: other port + throwaway DB):
cd oai/itests && OAI_BASE_URL=http://127.0.0.1:PORT uv run pytest tests/test_mcp.py
```

Generation needs an online `imggen.*` agent: run OffloadMQ locally (it binds `HOST`/`PORT`,
**not** `SERVER_ADDRESS`), set OAI admin settings to it, and use any agent that uploads to
`data.output_bucket` and resolves `{"images":[{"file_uid","filename"}]}` with status
`{"success": 1.0}` (camelCase). Inline `data_base64` images are accepted only by img-utils,
not by the imggen pipeline.

## Debugging

| Symptom | Look at |
|---------|---------|
| Claude: "Couldn't reach the MCP server" | `/.well-known/oauth-protected-resource/mcp` reachable? 401 has `resource_metadata`? |
| "Authorization with the MCP server failed" | `/oauth/token` response (form body, PKCE), redirect URI registered, `PUBLIC_BASE_URL` vs the URL typed |
| Works, then 401 after ~1 h | Refresh failing: rotated-token reuse revoked the grant (warn log "rotated refresh token reused") |
| Generation always "still running" | `image_pipeline_events` for the job (`worker.poll` errors), OffloadMQ agent, watch connection |
| Tool result truncated / no previews | Inline budget; use `view_image` or the links |
